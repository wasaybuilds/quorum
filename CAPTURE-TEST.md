# Capture Test

## Tool and model
- **Tool:** Claude Code (VS Code extension, Windows 11)
- **Model:** `claude-opus-5-5` (1M context), used for both planning and execution. No other model.
- **Automatic mechanism:** yes — Claude Code hooks (`UserPromptSubmit` and `Stop` lifecycle events).

## Mechanism
- Config file: [`.claude/settings.json`](.claude/settings.json) (project-level, committed).
- Both events run `node "$CLAUDE_PROJECT_DIR/.claude/hooks/capture-log.js"`.
- [`capture-log.js`](.claude/hooks/capture-log.js) reads the hook payload from stdin
  (`session_id`, `transcript_path`, `hook_event_name`), parses the session transcript
  (JSONL) and rewrites `.agent-logs/YYYY-MM-DD_HH-MM-SS_<session-id>.md` in the 8x format.
  - Each turn = the verbatim user prompt + the final assistant text of that turn
    (text after the last tool call). Thinking, tool calls and intermediate text are excluded.
  - UTC timestamps and the model name come from the transcript entries.
  - `UserPromptSubmit` records the prompt immediately (before it reaches the transcript);
    `Stop` records the final response.
  - The script never blocks the agent: failures go to stderr and it exits 0.

## What did not work first
- The setup page (`8x-internal.com/p/8x-agent-capture-setup`) returned only its title through a
  plain web fetch; the content lives in an iframe `srcDoc`, so it was extracted from the raw HTML.
- The first session was opened in the home directory (`C:\Users\Hp`), not the repo. Project
  hooks are loaded from the folder a session starts in, so they could not fire for that session.
  Its log was generated by running the same script once against that session's transcript
  (`node .claude/hooks/capture-log.js <transcript.jsonl>`); every later session is opened in the
  repo folder so the hooks fire on their own.
